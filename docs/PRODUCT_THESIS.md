# Igor — product thesis and decision filter

**Igor is your agent, with taste.** Its purpose is to make Qloo's cross-domain cultural intelligence useful to **ordinary people**. A person starts with a goal, not an API, and leaves with a discovery, decision, or creation they can use.

Igor is **not** a restaurant-soundscape service, gift app, travel planner, business analytics dashboard or generic chatbot. Those are possible outcomes composed from capabilities. No use case should quietly become its entire identity.

## Three user outcomes

- **Discover:** Reveal a surprising but meaningful connection between what someone already loves and an unfamiliar book, film, artist, design, experience or idea. Show attributable evidence, not popularity masquerading as relevance.
- **Decide:** Compare options using expressed taste **alongside** constraints. Qloo affinity does not verify price, location feasibility, availability, personal psychology, licensing or satisfaction.
- **Create:** Turn grounded cultural direction into an independently editable result. Changing one part preserves approved and unrelated work, while conflicts remain explicit.

## First-use promise

Accept an unfinished thought and offer one immediately useful first step. Do not require technical terms or lengthy taste onboarding. Only call Qloo when cultural intelligence can materially improve the goal; ordinary non-cultural questions must not trigger irrelevant calls. Ask for missing preferences only when truly necessary. Never fabricate them.

## Engineering decision filter

1. Does this capability help an ordinary person reach a recognizable outcome?
2. Would authentic cross-domain Qloo evidence *change* a meaningful choice or deliverable?
3. Can the user inspect the actual cultural source and the unknown facts?
4. Can the capability be reused across several kinds of goals, rather than a hardcoded vertical?
5. Can the user edit, approve, preserve and later refine the result without losing the thread?
6. Has the effect been measured against a credible baseline, instead of inferred from the presence of API calls?

The flagship demo is a **test vehicle** for the general-purpose agent, not its permanent product definition. When technically possible, show a second genuinely different goal using the same engine.

## Evidence standard

Repository tests establish engineering behavior, not user preference. A Qloo request establishes retrieval, not improved usefulness. Compare real outcomes against a competent baseline using identical user goals; assess relevance, meaningful novelty, actionability, trust and coherence with blinded human reviewers; audit factual claims separately. Publish no invented percentages or unfounded claims of causal lift.

## Build priority

Keep current connected-artifact and evidence work, but prioritize a truthful end-to-end cultural outcome and a reproducible blinded human comparison. Avoid expanding worker infrastructure, vertical-specific features or film production merely to imply readiness.
